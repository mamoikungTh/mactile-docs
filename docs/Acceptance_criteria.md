# Acceptance Criteria (เกณฑ์การยอมรับการส่งมอบ): Mactile (กลุ่ม 4) — MVP

> **ชื่อระบบ:** Mactile (Remote Device Lab & Queue Management System)  
> **กลุ่มผู้พัฒนา:** กลุ่ม 4  
> **ระดับโครงการ:** Minimum Viable Product (MVP)  
> **สถานะเอกสาร:** Approved / Baseline  
> **วันที่จัดทำ:** 16 สิงหาคม 2026  

---

## 1. บทนำและวัตถุประสงค์ (Introduction & Purpose)

เอกสารฉบับนี้กำหนด **เกณฑ์การยอมรับการส่งมอบ (Acceptance Criteria)** และ **เกณฑ์การตรวจรับระบบ (User Acceptance Testing - UAT Criteria)** สำหรับโครงการ **Mactile MVP (กลุ่ม 4)** เพื่อใช้เป็นมาตรฐานในการตรวจสอบว่า ซอฟต์แวร์ที่พัฒนาขึ้นมีความถูกต้อง ครบถ้วนตามข้อกำหนด และพร้อมสำหรับการส่งมอบและใช้งานจริง

### นิยามความสมบูรณ์ของการส่งมอบ (Definition of Done - DoD สำหรับ MVP)
ระบบจะถือว่าผ่านเกณฑ์การตรวจรับ MVP เมื่อ:
1. ฟังก์ชันการทำงานหลักทั้ง 4 โมดูลผ่านการทดสอบตามเกณฑ์ในเอกสารนี้ครบ 100%
2. ไม่พบข้อผิดพลาดระดับวิกฤต (Critical / Blocker Bugs) ที่ทำให้ระบบหยุดทำงานหรือเกิดข้อมูลรั่วไหล
3. มีการทดสอบการใช้งานจริงแบบ End-to-End ตั้งแต่จองคิว -> รีโมทใช้งาน -> รีเซ็ตเครื่อง -> ส่งต่อคิวถัดไป ได้อย่างราบรื่น
4. เอกสารประกอบโครงการ เช่น [docs/project_charter.md](file:///D:/LAB-DOC/docs/project_charter.md) และ [docs/requirements_specification.md](file:///D:/LAB-DOC/docs/requirements_specification.md) มีเนื้อหาสอดคล้องกัน

### โมดูลที่ 1: ระบบการจองคิวและการเข้าถึง (Queue & Access Management)

#### AC-QUE-01: การแสดงสถานะเครื่องแบบ Real-time
* **คำอธิบาย:** หน้าเว็บต้องแสดงรายการเครื่องและสถานะปัจจุบันได้อย่างถูกต้อง
* **Scenario:**
  * **Given:** ผู้ใช้เปิดหน้าเว็บ Mactile
  * **When:** หน้าจอโหลดเสร็จสมบูรณ์
  * **Then:** ระบบต้องแสดงการ์ดเครื่อง Target Host พร้อมสถานะที่ถูกต้อง (`Available`, `Busy`, `Cleaning`, `Maintenance`, `Offline`) โดยข้อมูลต้องตรงกับสถานะจริงของเครื่องในแล็บ

#### AC-QUE-02: การเข้าคิวแบบ FIFO และการป้องกันการจองซ้อน
* **คำอธิบาย:** ผู้ใช้สามารถกดรับคิว และระบบต้องจัดสรรลำดับคิวอย่างเป็นธรรม
* **Scenario:**
  * **Given:** เครื่อง Target มีผู้ใช้อื่นกำลังใช้งานอยู่ (`Busy`)
  * **When:** ผู้ใช้กดปุ่ม "เข้าคิวใช้งาน" (Join Queue)
  * **Then:** ระบบต้องเพิ่มผู้ใช้เข้าสู่ตารางคิว FIFO แสดงหมายเลขลำดับคิว และไม่อนุญาตให้ผู้ใช้คนเดิมกดจองเครื่องเดิมซ้ำอีก

#### AC-QUE-03: การแจ้งเตือนเมื่อถึงคิวและการ Claim สิทธิ์
* **คำอธิบาย:** เมื่อเครื่องว่างและถึงคิว ระบบต้องแจ้งให้ผู้ใช้ทราบและกำหนดเวลา Claim
* **Scenario:**
  * **Given:** ผู้ใช้อยู่ในสถานะ "รอคิวลำดับถัดไป" และเครื่อง Target กลับสู่สถานะ `Available`
  * **When:** ระบบประมวลผลจัดสรรคิว
  * **Then:** หน้าจอของผู้ใช้ต้องเปลี่ยนเป็นสถานะ "ถึงคิวของคุณแล้ว" พร้อมเวลานับถอยหลังการยืนยันสิทธิ์ (Claim Timeout ภายใน 3-5 นาที) หากผู้ใช้ไม่กดยืนยัน ระบบจะข้ามไปยังคิวถัดไปอัตโนมัติ

#### AC-QUE-04: การควบคุมเวลาและการนับเวลาถอยหลังของ Session
* **คำอธิบาย:** มีตัวนับเวลาถอยหลังบนหน้าจอ และแจ้งเตือนก่อนหมดเวลา
* **Scenario:**
  * **Given:** ผู้ใช้เริ่มเข้าสู่ Session การใช้งาน
  * **When:** เวลาการใช้งานดำเนินไป
  * **Then:** มี Countdown Timer แสดงเวลาคงเหลือชัดเจน และมีการแจ้งเตือนเมื่อเหลือเวลา 5 นาทีสุดท้าย

#### AC-QUE-05: การกดยุติ Session ก่อนเวลา (End Session Early)
* **คำอธิบาย:** ผู้ใช้สามารถกดคืนเครื่องก่อนหมดเวลาได้
* **Scenario:**
  * **Given:** ผู้ใช้อยู่ใน Session ที่กำลัง Active
  * **When:** ผู้ใช้กดปุ่ม "สิ้นสุดการใช้งาน" (End Session) และกดยืนยัน
  * **Then:** สิทธิ์การเชื่อมต่อของผู้ใช้จะถูกยกเลิกทันที และระบบจะส่งคำสั่งเริ่มกระบวนการ Cleanup เครื่องทันที

### โมดูลที่ 2: การจัดการและรีเซ็ตสภาพแวดล้อมเบื้องต้น (Environment Management & Basic Reset)

#### AC-ENV-01: การตัดการเชื่อมต่อทันทีหลังสิ้นสุด Session
* **คำอธิบาย:** เมื่อหมดเวลาหรือถูกตัดสิทธิ์ โปรแกรมรีโมทต้องถูกปิดการเชื่อมต่อ
* **Scenario:**
  * **Given:** ผู้ใช้กำลังเชื่อมต่อรีโมทอยู่บนเครื่อง Target Host
  * **When:** เวลาของ Session ลดลงเหลือ 00:00 หรือได้รับคำสั่ง Terminate
  * **Then:** Session การรีโมทต้องถูกตัดขาดทันที ผู้ใช้ไม่สามารถควบคุมหน้าจอหรือส่ง Input ใดๆ ได้อีก

#### AC-ENV-02: การกวาดล้างไฟล์ชั่วคราวและ Workspace
* **คำอธิบาย:** ไฟล์ที่ผู้ใช้สร้างหรือดาวน์โหลดไว้ต้องถูกลบทิ้ง
* **Scenario:**
  * **Given:** ผู้ใช้ได้สร้างไฟล์ไว้บน `Desktop`, `Downloads` และโฟลเดอร์ `Temp`
  * **When:** ระบบรันสคริปต์ Cleanup หลังจบ Session
  * **Then:** ไฟล์ทั้งหมดใน `Desktop`, `Downloads`, `Temp` และใน `Recycle Bin/Trash` ต้องถูกลบออกอย่างสมบูรณ์

#### AC-ENV-03: การปิดโปรแกรมและ Kill Processes ค้าง
* **คำอธิบาย:** โปรแกรมที่ผู้ใช้เปิดไว้ต้องถูกปิดทั้งหมด
* **Scenario:**
  * **Given:** ผู้ใช้เปิดโปรแกรมทิ้งไว้ เช่น Google Chrome, VS Code, Terminal หรือโปรแกรมอื่นๆ
  * **When:** สคริปต์ Cleanup ทำงาน
  * **Then:** Process ของโปรแกรมที่ผู้ใช้เปิดไว้ต้องถูก Kill ทิ้งทั้งหมด ไม่เหลือทำงานค้างใน Background

#### AC-ENV-04: การล้างแคชและประวัติของเว็บเบราว์เซอร์
* **คำอธิบาย:** ป้องกันการจดจำรหัสผ่านหรือบัญชีของผู้ใช้คนก่อนหน้า
* **Scenario:**
  * **Given:** ผู้ใช้ได้ล็อกอินบัญชีเว็บไซต์ไว้ในเว็บเบราว์เซอร์ของเครื่อง Target
  * **When:** สคริปต์ Cleanup ทำงาน
  * **Then:** History, Cache, Cookies และ Session Login ทั้งหมดในเบราว์เซอร์ต้องถูกล้างออก ไม่มีการล็อกอินค้างไว้

#### AC-ENV-05: การหมุนเวียนรหัสผ่านรีโมทใหม่ (Password Rotation)
* **คำอธิบาย:** ป้องกันผู้ใช้เดิมนำรหัสผ่านเดิมมาแอบเข้าเครื่องซ้ำ
* **Scenario:**
  * **Given:** Session เดิมสิ้นสุดลง
  * **When:** สคริปต์ Cleanup ดำเนินการขั้นสุดท้าย
  * **Then:** Host Agent ต้องสุ่มสร้างรหัสผ่านการเชื่อมต่อรีโมทใหม่ (New Dynamic Password) และอัปเดตไปยังระบบ Remote Service ทำให้รหัสผ่านเดิมใช้งานไม่ได้อีกต่อไป

#### AC-ENV-06: การส่งผลการ Reset และปรับสถานะเครื่องอัตโนมัติ
* **คำอธิบาย:** รายงานผลความพร้อมกลับมายังระบบส่วนกลาง
* **Scenario:**
  * **Given:** สคริปต์ Cleanup ทำงานครบทุกขั้นตอนสำเร็จ
  * **When:** Host Agent ตรวจสอบความเรียบร้อย (Health Check)
  * **Then:** ส่งสัญญาณ `CLEANUP_SUCCESS` กลับมายังเซิร์ฟเวอร์ และเซิร์ฟเวอร์ปรับสถานะเครื่องจาก `Cleaning` เป็น `Available` เพื่อรับคิวถัดไป

### โมดูลที่ 3: การเชื่อมต่อรีโมทด้วยโปรแกรมสำเร็จรูป (Remote Connection Integration)

#### AC-REM-01: ความถูกต้องของข้อมูลการเชื่อมต่อ (Connection Details)
* **คำอธิบาย:** ผู้ใช้ได้รับข้อมูลสำหรับเปิดโปรแกรมรีโมทอย่างถูกต้อง
* **Scenario:**
  * **Given:** ผู้ใช้ได้รับสิทธิ์ Session บนเครื่อง Target
  * **When:** ผู้ใช้เปิดดูหน้ารายละเอียดการเชื่อมต่อ
  * **Then:** ระบบต้องแสดงข้อมูลครบถ้วน ได้แก่:
    1. ชื่อเครื่องและ IP Address / RustDesk ID / VNC Port
    2. รหัสผ่านชั่วคราว (One-Time / Dynamic Password)
    3. ปุ่ม Copy ข้อมูลแบบคลิกเดียว
    4. คำแนะนำการเปิดโปรแกรมรีโมท Client

#### AC-REM-02: ความสามารถในการควบคุมเครื่องระยะไกลได้จริง
* **คำอธิบาย:** ผู้ใช้สามารถนำข้อมูลไปกรอกใน Client สำเร็จรูปและควบคุมเครื่องได้
* **Scenario:**
  * **Given:** ผู้ใช้เปิดโปรแกรมสำเร็จรูป (เช่น RustDesk Client หรือ VNC Viewer) บนเครื่องของตนเอง
  * **When:** ผู้ใช้กรอก Connection ID และรหัสผ่านที่ได้รับจากระบบ Mactile
  * **Then:** โปรแกรมต้องเชื่อมต่อไปยัง Target Host ได้สำเร็จ สามารถมองเห็นหน้าจอ ส่งสัญญาณแป้นพิมพ์ และเลื่อนเมาส์ควบคุมได้ตามปกติ

#### AC-REM-03: การปฏิเสธการเชื่อมต่อเมื่อรหัสผ่านหมดอายุ
* **คำอธิบาย:** การใช้ Credential เก่าต้องถูกปฏิเสธ
* **Scenario:**
  * **Given:** ผู้ใช้ Session เดิมพยายามนำรหัสผ่านเดิมที่เคยได้ไปเชื่อมต่อซ้ำหลังหมดเวลา
  * **When:** ส่ง Request เชื่อมต่อไปยัง Target Host
  * **Then:** โปรแกรมรีโมทต้องปฏิเสธการเข้าถึง (Authentication Failed / Access Denied) ทันที

### โมดูลที่ 4: หน้า Dashboard ผู้ดูแลระบบ (Admin Dashboard)

#### AC-ADM-01: การแสดงผล Live Monitoring & Queue List
* **คำอธิบาย:** Admin เห็นภาพรวมเครื่องและคิวทั้งหมด
* **Scenario:**
  * **Given:** Admin ล็อกอินเข้าสู่หน้า Admin Dashboard
  * **When:** หน้าจอ Dashboard โหลดเสร็จ
  * **Then:** ระบบต้องแสดง:
    1. Grid การ์ดแสดงเครื่องทั้งหมด พร้อมสถานะสีชัดเจน
    2. รายชื่อผู้ใช้ที่กำลัง Active ในแต่ละเครื่อง และเวลาที่เหลือ
    3. ตารางรายการคิวที่กำลังรออยู่ทั้งหมด พร้อมลำดับคิว

#### AC-ADM-02: การทำงานของปุ่ม Force Kick (ตัดสิทธิ์ฉุกเฉิน)
* **คำอธิบาย:** Admin สามารถตัดผู้ใช้ที่ทำผิดกฎหรือเครื่องค้างได้ทันที
* **Scenario:**
  * **Given:** มีผู้ใช้งานกำลัง Active อยู่ในเครื่อง Target เครื่องหนึ่ง
  * **When:** Admin กดปุ่ม "Force Kick / Terminate" และกดยืนยัน
  * **Then:** ระบบต้องตัดการเชื่อมต่อของผู้ใช้นั้นทันที ยุติ Session และสั่งให้เครื่องเข้าสู่กระบวนการ `Cleaning`

#### AC-ADM-03: การทำงานของปุ่ม Force Reset เครื่อง
* **คำอธิบาย:** Admin สามารถสั่งรันสคริปต์ Cleanup ได้ตามต้องการ
* **Scenario:**
  * **Given:** เครื่อง Target เครื่องใดเครื่องหนึ่ง (ไม่ว่าจะอยู่ในสถานะใด)
  * **When:** Admin กดปุ่ม "Force Reset"
  * **Then:** Host Agent ประจำเครื่องนั้นต้องสั่งรันสคริปต์ Cleanup ใหม่ทันที และปรับสถานะบน Dashboard เป็น `Cleaning` จนกว่าจะเสร็จสิ้น

#### AC-ADM-04: การตั้งค่า Maintenance Mode
* **คำอธิบาย:** Admin สามารถปิดรับคิวของเครื่องที่ชำรุดหรือต้องการซ่อมแซมได้
* **Scenario:**
  * **Given:** เครื่อง Target อยู่ในสถานะปกติ
  * **When:** Admin สลับสวิตช์เป็น "Maintenance Mode"
  * **Then:** สถานะเครื่องต้องเปลี่ยนเป็น `Maintenance` ผู้ใช้ทั่วไปจะไม่สามารถกดจองคิวเครื่องนี้ได้ และหากมีคิวรออยู่ ระบบต้องแจ้งเตือนหรือย้ายคิวตามนโยบาย

#### AC-ADM-05: การตรวจสอบ Activity & Audit Logs
* **คำอธิบาย:** บันทึกประวัติการทำงานของระบบอย่างละเอียด
* **Scenario:**
  * **Given:** มีการทำกิจกรรมในระบบ (การจอง, การเริ่ม Session, การตัดคิว, การ Reset เครื่อง)
  * **When:** Admin เปิดดูแถบ "Audit Logs" บน Dashboard
  * **Then:** ระบบต้องแสดงรายการบันทึกเหตุการณ์พร้อม Timestamp, User ID/Admin ID, Action Name, และผลลัพธ์ได้อย่างถูกต้อง

| **AC-NFR-01** | **เวลาในการรีเซ็ต (Reset Duration)** | กระบวนการรันสคริปต์ Cleanup จนเครื่องกลับมาสถานะ `Available` ต้องใช้เวลาไม่เกิน **90 วินาที** | 🟩 ต้องผ่าน |
| **AC-NFR-02** | **ความปลอดภัยของข้อมูล (Data Privacy)** | หลังกระบวนการ Reset ต้องไม่พบไฟล์ ประวัติเว็บ หรือการล็อกอินค้างของผู้ใช้คนก่อนหน้า 100% | 🟩 ต้องผ่าน |
| **AC-NFR-03** | **การตรวจจับเครื่องหลุด (Heartbeat Monitoring)** | หากปิดเครื่อง Target หรือดึงสาย LAN ระบบ Dashboard ต้องตรวจพบและปรับสถานะเป็น `Offline` ภายใน **30 วินาที** | 🟩 ต้องผ่าน |
| **AC-NFR-04** | **เวลาตอบสนองของระบบ (API Response Time)** | การกดยื่นคิว / เปลี่ยนสถานะ ต้องแสดงผลบนหน้าจอภายในไม่เกิน **1 วินาที** | 🟩 ต้องผ่าน |
| **AC-NFR-05** | **ความถูกต้องของคิว (Queue Integrity)** | ระบบต้องไม่จ่ายสิทธิ์ผู้ใช้ 2 คนเข้าเครื่องเดียวกันพร้อมกันโดยเด็ดขาด (No Race Condition) | 🟩 ต้องผ่าน |
